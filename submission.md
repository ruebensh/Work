## Часть 4. Об использовании ИИ

В работе над проектом я использовал **Antigravity IDE** (на базе Gemini) как основной ИИ-инструмент. Лучший результат давали конкретные, узкие промпты — например, «напиши Pydantic-валидатор, который нормализует номер телефона так же, как уже существующий в StudentCreate» работало гораздо точнее, чем просто «добавь валидацию». Для генерации шаблонного кода (FastAPI-роутеры, SQLAlchemy-модели, структура тестов) ИИ справился быстро и без замечаний.

Ошибки тоже были. В модуле `bot/formatting.py` ИИ вынес функцию `format_amount` внутрь другой функции в виде строки-докстринга — фактически функция перестала существовать как таковая. Обнаружил это при запуске `pytest`: тест упал с `ImportError: cannot import name 'format_amount'`. Пришлось вручную просмотреть файл и восстановить определение функции на верхнем уровне модуля. Аналогичная проблема возникла в `app/schemas.py` — класс `StudentUpdate` с его методами оказался с неправильным отступом внутри чужого блока, из-за чего `conftest.py` падал при сборе тестов; нашёл через traceback и поправил вручную.

Сам я написал логику валидации данных (решение о том, какие именно проверки нужны и почему), структуру коммитов и итоговую компоновку файлов. ИИ генерировал реализацию — код функций, заготовки тестов, CSS-стили для веб-страницы. Финальный просмотр и проверку корректности каждого изменения делал я сам.
